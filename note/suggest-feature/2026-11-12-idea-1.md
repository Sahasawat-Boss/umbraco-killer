## ⚠️ ควรแก้ก่อนเพิ่มของใหม่

### 1. Stored XSS ใน Rich Text ทำให้ Writer ยกสิทธิ์ตัวเองเป็น Admin ได้
- **ปัญหา:** ค่า HTML ของ `Killer.RichText` ถูกบันทึกลงฐานข้อมูลแบบดิบ ไม่มีการ sanitize ที่ไหนเลย (grep `sanitiz` แล้วไม่เจอ)
  - ฝั่ง backoffice: [PropertyEditor.tsx](../../src/components/editors/PropertyEditor.tsx) ฟังก์ชัน `RichText` ใช้ `ref.current.innerHTML = value`
  - ฝั่งเว็บ: [page.tsx](../../src/app/[[...slug]]/page.tsx) และ [Blocks.tsx](../../src/components/site/Blocks.tsx) ใช้ `dangerouslySetInnerHTML`
- **ทำไมสำคัญ:** Writer ซึ่งเป็นสิทธิ์ต่ำสุดเปิดโหมด HTML แล้วใส่ `<img src=x onerror=...>` ได้ พอ Admin เปิดเอกสารนั้น โค้ดจะรันใน session ของ Admin และเรียก server action `saveUser` ได้ทันที คุกกี้เป็น httpOnly ก็จริง แต่ server action ใช้ session ของเบราว์เซอร์อยู่แล้ว จึงไม่ได้ช่วยกันกรณีนี้
- **แก้:** sanitize ฝั่ง server ตอน `cleanValues` (ทั้ง RichText ปกติและที่อยู่ใน block) ด้วย allowlist ของ tag/attribute ที่ toolbar สร้างได้ (`p h2 h3 strong em u a ul ol li blockquote img br`) และตัด `on*` กับ `javascript:` ทิ้ง
- **ไฟล์:** `src/actions/content.ts`, เพิ่ม `src/lib/sanitize-html.ts`
- **Effort:** S–M

### 2. ลบ Element Type ที่ยังมี block ใช้อยู่ได้ แล้วข้อมูลหายเงียบ ๆ
- **ปัญหา:** `deleteDocumentType` ใน [settings.ts](../../src/actions/settings.ts) เช็คแค่ `db.document.count` แต่ Element Type ไม่มี document ผูกอยู่ จึงลบได้เสมอ หลังลบแล้ว `cleanValues` จะตัด block ที่ Element Type หายไปทิ้งตอน save ครั้งถัดไป ทำให้เนื้อหาหายโดยไม่มีอะไรเตือน
- **แก้:** ตอนลบให้สแกน `values`/`publishedValues` หา `contentTypeId` ถ้ายังมีคนใช้ให้ปฏิเสธ และให้ลบ id นั้นออกจาก `config.blocks` ของ Data Type แบบ Block List ด้วย
- **Effort:** S

### 3. Writer ลบเอกสารถาวรและล้าง Recycle Bin ได้
- **ปัญหา:** `deleteDocument` และ `emptyRecycleBin` ใน `src/actions/content.ts` เช็คแค่ `requireUser()` ซึ่งไม่ตรงกับเจตนาของ role (Writer ยัง publish ไม่ได้ แต่ลบถาวรได้) และ login ก็ไม่มี rate limit
- **แก้:** ให้ action ที่ทำลายข้อมูลใช้ `canPublish` หรือเพิ่มฟังก์ชัน `canDelete` และหน่วงเวลาหรือนับจำนวนครั้งที่ login ผิดใน `loginAction`
- **Effort:** S

## Quick win (< ครึ่งวัน)

### 4. Preview ฉบับร่าง ("Save and preview")
- **คืออะไร:** ปุ่มใน ContentEditor ที่เปิดหน้าเว็บโดยใช้ค่า `values` ของฉบับร่างแทน `publishedValues` (เปิดได้เฉพาะผู้ที่ login อยู่)
- **ทำไม:** ระบบรู้อยู่แล้วว่ามี "Pending changes" (`edited`) แต่ทั้งหน้าเว็บและ `contentToApi` อ่านแค่ `publishedValues` ตอนนี้ editor ต้องกด publish ก่อนถึงจะเห็นผล ยิ่งเมื่อมี Block List ที่จัดหน้าเองได้ การดูก่อน publish ก็ยิ่งจำเป็น
- **ไฟล์:** `src/lib/delivery.ts` (เพิ่ม option `preview`), `src/app/[[...slug]]/page.tsx` (`?preview=1` + เช็ค `getCurrentUser`), `src/components/backoffice/ContentEditor.tsx`
- **Effort:** S

### 5. sitemap.xml + robots.txt
- **คืออะไร:** ไฟล์ `app/sitemap.ts` และ `app/robots.ts` ที่สร้างจาก `computeRoutes` โดยข้ามหน้าที่ติ๊ก `hideFromNavigation`
- **ทำไม:** มี `metaTitle`/`metaDescription` และ routing เต็มรูปแบบแล้ว แต่ยังไม่มี sitemap เลย (grep แล้วไม่เจอ) ใช้ข้อมูลที่มีอยู่ได้ทั้งหมด
- **ไฟล์:** `src/app/sitemap.ts`, `src/app/robots.ts`, `src/lib/routes.ts`
- **Effort:** S

## Impact สูง

### 6. Redirect อัตโนมัติเมื่อ URL เปลี่ยน
- **คืออะไร:** ตาราง `RedirectUrl` ที่บันทึก route เก่าทุกครั้งที่ชื่อเปลี่ยนหรือมีการย้ายเอกสาร แล้วหน้าเว็บตอบ 301 ไปที่ URL ใหม่ พร้อมหน้าจัดการใน Content
- **ทำไม:** `saveDocument` ตั้ง `urlSegment: slugify(name)` ใหม่ทุกครั้งที่ save และ `moveDocument` ก็เปลี่ยน path ด้วย การแก้ชื่อหน้าเพียงครั้งเดียวจึงทำให้ลิงก์เก่าและ SEO พังทันที ฟีเจอร์นี้อยู่ใน README "Not implemented yet"
- **ไฟล์:** `prisma/schema.prisma`, `src/actions/content.ts`, `src/app/[[...slug]]/page.tsx`, `src/app/api/delivery/v2/content/item/[...idOrPath]/route.ts`
- **Effort:** M

### 7. Scheduled publish / unpublish
- **คืออะไร:** ตั้งวันเวลา publish หรือ unpublish ได้ที่แท็บ Info แล้วให้งานที่รันตามเวลา (cron route) ทำให้
- **ทำไม:** โครงพร้อมแล้ว ทั้ง `publishedAt`, การตรวจ validation ตอน publish และ audit log ขาดแค่ฟิลด์เวลากับตัว runner อยู่ใน README "Not implemented yet" เหมือนกัน
- **ไฟล์:** `prisma/schema.prisma` (`publishAt`, `unpublishAt`), `src/actions/content.ts`, `src/app/api/cron/publish/route.ts`, `ContentEditor.tsx` (InfoView)
- **Effort:** M

### 8. Webhook เมื่อ publish (สำหรับ frontend แบบ headless)
- **คืออะไร:** ตั้งค่า URL ที่ Settings แล้วระบบจะ POST `{ event, id, route, contentType }` ไปทุกครั้งที่มีการ publish, unpublish หรือ delete
- **ทำไม:** โปรเจกต์ขายตัวเองว่ามี Delivery API แบบ v2 ไว้ให้ frontend อื่นดึงข้อมูล แต่ frontend ภายนอกไม่มีทางรู้ว่าเนื้อหาเปลี่ยนตอนไหน ตอนนี้ `refresh()` ทำแค่ `revalidatePath` ภายในแอปเอง
- **ไฟล์:** `prisma/schema.prisma` (`Webhook`), `src/actions/content.ts`, หน้าใหม่ใน `src/app/umbraco/section/settings/webhooks/`
- **Effort:** M

- **ไฟล์:** `src/app/media/[...path]/route.ts`, `src/lib/delivery.ts` (`mediaToApi` เพิ่ม url ที่ระบุขนาด), `src/components/site/Blocks.tsx`
